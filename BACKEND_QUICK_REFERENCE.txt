⚡ HOW THE INVERTER WILL COMMUNICATE
═══════════════════════════════════════════════════════════════════════════════

1. REGISTRATION:
   Inverter sends: { serial_number, model, firmware, mac_address }
   Backend responds: { inverter_token, heartbeat_interval }

2. DATA PUSH (Every 30 seconds):
   Inverter sends:
   {
     "timestamp": "2024-06-11T14:30:45Z",
     "solar_power_w": 2850,
     "grid_power_w": -500,
     "load_power_w": 1200,
     "battery_charge_percent": 85,
     ... (other sensor data)
   }

3. HEARTBEAT (Every 5 minutes):
   Inverter sends: { status check }
   Backend responds: { ok, config_updates? }

4. EVENTS:
   Inverter sends: { grid_disconnect, battery_low, over_temp, etc }

5. STATUS QUERIES:
   Backend checks: GET /devices/{inverter_id}/status
