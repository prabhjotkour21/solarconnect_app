1. TECH STACK RECOMMENDATIONS
===============================================================================

PRIMARY STACK (RECOMMENDED):
├─ Runtime: Node.js (v18+) or Python (3.10+)
├─ Framework: Express.js (Node) OR FastAPI/Django (Python)
├─ Database: PostgreSQL (primary) + Redis (caching)
├─ Authentication: JWT + OAuth2 (optional: Firebase Auth)
├─ Cloud: AWS/Google Cloud/Azure
├─ APIs: REST or GraphQL
└─ Real-time: WebSockets or Socket.io (for live updates)

ALTERNATIVE STACK:
├─ Runtime: Java/Spring Boot
├─ Database: MongoDB + PostgreSQL
├─ Cloud: Heroku or Railway
└─ APIs: REST + gRPC

RECOMMENDED CHOICE: Node.js + Express + PostgreSQL
(Fastest to develop, excellent tooling, JavaScript/TypeScript support)

2. DATABASE SCHEMA DESIGN
===============================================================================

CORE TABLES:

A) USERS TABLE
─────────────────────────────────────────────────────────────────────────────
Columns:
- user_id (UUID, Primary Key)
- email (VARCHAR, UNIQUE, NOT NULL)
- phone (VARCHAR, UNIQUE)
- password_hash (VARCHAR, NOT NULL)
- full_name (VARCHAR)
- profile_picture_url (VARCHAR)
- location (VARCHAR)
- timezone (VARCHAR, default: UTC)
- language (VARCHAR, default: English)
- theme_preference (ENUM: dark/light)
- created_at (TIMESTAMP)
- updated_at (TIMESTAMP)
- last_login (TIMESTAMP)
- is_active (BOOLEAN)
- verification_status (ENUM: pending/verified)

B) INVERTERS TABLE
─────────────────────────────────────────────────────────────────────────────
Columns:
- inverter_id (UUID, Primary Key)
- user_id (UUID, Foreign Key → users.user_id)
- serial_number (VARCHAR, UNIQUE, NOT NULL)
- model_name (VARCHAR)
- manufacturer (VARCHAR)
- firmware_version (VARCHAR)
- capacity_kva (DECIMAL)
- installation_date (DATE)
- warranty_expiry (DATE)
- ip_address (VARCHAR)
- mac_address (VARCHAR)
- is_paired (BOOLEAN)
- pairing_date (TIMESTAMP)
- last_sync (TIMESTAMP)
- status (ENUM: online/offline/error)
- created_at (TIMESTAMP)
- updated_at (TIMESTAMP)

C) ENERGY_READINGS TABLE
─────────────────────────────────────────────────────────────────────────────
Columns:
- reading_id (UUID, Primary Key)
- inverter_id (UUID, Foreign Key → inverters.inverter_id)
- timestamp (TIMESTAMP, NOT NULL, INDEXED)
- solar_power_w (DECIMAL)
- grid_power_w (DECIMAL)
- load_power_w (DECIMAL)
- battery_power_w (DECIMAL)
- battery_charge_percent (DECIMAL)
- solar_today_kwh (DECIMAL)
- grid_import_kwh (DECIMAL)
- grid_export_kwh (DECIMAL)
- battery_health_percent (DECIMAL)
- temperature_c (DECIMAL)
- humidity_percent (DECIMAL)
- signal_strength (INTEGER)
- created_at (TIMESTAMP)

D) DAILY_SUMMARY TABLE (Aggregated data)
─────────────────────────────────────────────────────────────────────────────
Columns:
- summary_id (UUID, Primary Key)
- inverter_id (UUID, Foreign Key)
- date (DATE)
- total_solar_kwh (DECIMAL)
- total_grid_import_kwh (DECIMAL)
- total_grid_export_kwh (DECIMAL)
- avg_battery_percent (DECIMAL)
- max_power_w (DECIMAL)
- avg_power_w (DECIMAL)
- self_consumption_percent (DECIMAL)
- peak_time (TIME)
- reading_count (INTEGER)
- created_at (TIMESTAMP)

E) MONTHLY_SUMMARY TABLE (Aggregated data)
─────────────────────────────────────────────────────────────────────────────
Columns:
- summary_id (UUID, Primary Key)
- inverter_id (UUID, Foreign Key)
- year (INTEGER)
- month (INTEGER)
- total_solar_kwh (DECIMAL)
- total_grid_import_kwh (DECIMAL)
- total_grid_export_kwh (DECIMAL)
- days_with_data (INTEGER)
- created_at (TIMESTAMP)

F) POWER_CUT_EVENTS TABLE
─────────────────────────────────────────────────────────────────────────────
Columns:
- event_id (UUID, Primary Key)
- inverter_id (UUID, Foreign Key)
- start_time (TIMESTAMP)
- end_time (TIMESTAMP)
- duration_minutes (INTEGER)
- severity (ENUM: low/medium/high)
- notes (TEXT)
- created_at (TIMESTAMP)

G) NOTIFICATIONS TABLE
─────────────────────────────────────────────────────────────────────────────
Columns:
- notification_id (UUID, Primary Key)
- user_id (UUID, Foreign Key)
- inverter_id (UUID, Foreign Key)
- title (VARCHAR)
- description (TEXT)
- type (ENUM: alert/info/update/saving)
- priority (ENUM: low/medium/high/critical)
- is_read (BOOLEAN)
- action_url (VARCHAR)
- created_at (TIMESTAMP)
- read_at (TIMESTAMP)

H) ENVIRONMENTAL_DATA TABLE
─────────────────────────────────────────────────────────────────────────────
Columns:
- env_id (UUID, Primary Key)
- inverter_id (UUID, Foreign Key)
- date (DATE)
- co2_saved_kg (DECIMAL)
- trees_equivalent (DECIMAL)
- fuel_saved_liters (DECIMAL)
- water_saved_liters (DECIMAL)
- created_at (TIMESTAMP)

I) FINANCIAL_DATA TABLE
─────────────────────────────────────────────────────────────────────────────
Columns:
- financial_id (UUID, Primary Key)
- inverter_id (UUID, Foreign Key)
- date (DATE)
- savings_amount (DECIMAL)
- revenue_from_export (DECIMAL)
- subsidy_claimed (DECIMAL)
- total_kwh_saved_cost (DECIMAL)
- created_at (TIMESTAMP)

J) SETTINGS TABLE
─────────────────────────────────────────────────────────────────────────────
Columns:
- setting_id (UUID, Primary Key)
- user_id (UUID, Foreign Key)
- inverter_id (UUID, Foreign Key)
- electricity_rate_per_kwh (DECIMAL)
- currency (VARCHAR)
- notifications_enabled (BOOLEAN)
- daily_summary_time (TIME)
- alert_threshold_percent (INTEGER)
- created_at (TIMESTAMP)
- updated_at (TIMESTAMP)

INDEXES:
- users(email) - UNIQUE
- inverters(user_id) - for user queries
- inverters(serial_number) - UNIQUE
- energy_readings(inverter_id, timestamp DESC) - COMPOSITE, for time-series queries
- daily_summary(inverter_id, date) - COMPOSITE
- power_cut_events(inverter_id, start_time) - COMPOSITE
- notifications(user_id, is_read, created_at) - COMPOSITE

6. INVERTER INTEGRATION GUIDE
═══════════════════════════════════════════════════════════════════════════════

HOW THE INVERTER WILL COMMUNICATE WITH BACKEND:
─────────────────────────────────────────────────────────────────────────────

1. INVERTER REGISTRATION:
   Inverter → POST /inverters/register
   {
     "serial_number": "9AL1021Z100407",
     "model": "Hybrid 5KVA",
     "firmware": "v2.1.4",
     "mac_address": "00:1A:2B:3C:4D:5E"
   }
   Response: { inverter_token, heartbeat_interval: 30000 }

2. DATA PUSH (Every 30 seconds):
   Inverter → POST /inverters/{id}/readings
   Headers: Authorization: Bearer {inverter_token}
   {
     "timestamp": "2024-06-11T14:30:45Z",
     "solar_power_w": 2850,
     "grid_power_w": -500,
     "load_power_w": 1200,
     "battery_power_w": 0,
     "battery_charge_percent": 85,
     "temperature_c": 35,
     "humidity_percent": 65,
     "signal_strength": -45
   }

3. HEARTBEAT (Every 5 minutes):
   Inverter → POST /inverters/{id}/heartbeat
   Response: { status: "ok", config_update?: {...} }

4. EVENT NOTIFICATIONS:
   Inverter → POST /inverters/{id}/events
   Types: grid_disconnect, grid_reconnect, battery_low, over_temp, etc.

5. STATUS QUERIES (On demand):
   Backend → GET /devices/{inverter_id}/status
   Inverter checks status of backend connection & configuration
